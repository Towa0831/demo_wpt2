# ウッドプラスチックテクノロジーポータル（GitHubのIssueから更新する仕組み）

GitHubのIssueに `@claude` と書いて頼むだけで、ニュースの作成、採用情報の更新、文章の修正、画像の差し替えなどができるホームページです。更新作業はすべてGitHubの中で完結します。

```
① Issueに「@claude ○○したい」と書いて作成
      ↓ 自動
② Claudeがコメントで返事（質問・文章の提案・修正内容の報告）
      ↓ 「@claude これでOK」とコメント（小さな修正は①のあとすぐ保存されます）
③ Claudeが下書きを保存
      ↓ 自動
④ 確認用ページ（GitHub Pages）が更新され、URLがコメントで届く
      ↓ 見た目を確認して、Claudeの返事の「Create PR」から公開申請を作る
⑤ 公開申請で「Squash and merge」→「Confirm squash and merge」
      ↓ 自動
⑥ 本番サイトに反映（https://yamaguchi-index.com/demo_wpt2/）
```

- **予約公開**：ニュースの日付を未来にすると、その日の朝6時ごろに自動で公開されます
- **取り下げは削除**：ニュース・求人・職種・社員紹介を取り下げるときは、AIが中身・ページ・その項目だけで使っていた画像を消します（`tools/remove.py`）。消したものは変更の記録に残り、「前に出していた求人をもう一度出したい」と頼めば、記録から探して元どおりに戻せます（`tools/history.py`）
- **下書き・非公開**：ニュースや求人を「下書き」にすると確認用ページにだけ表示されます。「サイトに残したまま隠したい」とはっきり頼んだときだけ「非公開」にします（どちらにも表示されません）
- **差し戻し**：すべての変更が履歴として残るので、いつでも前の状態に戻せます
- **画像の自動調整**：スマートフォンの大きな写真も、自動で縮小・向きの補正・撮影場所などの情報の削除をしてから使います

## 1. 最初の設定（1回だけ）

### 1-1. Claude GitHub App をリポジトリに入れる

1. https://github.com/apps/claude を開き、「Configure」を押します
2. 自分のアカウントを選び、「Only select repositories」でこのリポジトリを追加して保存します

### 1-2. シークレットを登録する

**Settings → Secrets and variables → Actions** に、次の4つを登録します。

| 名前 | 中身 |
| --- | --- |
| `CLAUDE_CODE_OAUTH_TOKEN` | パソコンのターミナルで `claude setup-token` を実行して表示されたトークン |
| `FTP_SERVER` | XserverのFTPホスト名（`sv○○○○.xserver.jp` の形） |
| `FTP_USERNAME` | FTPのユーザー名 |
| `FTP_PASSWORD` | FTPのパスワード |

### 1-3. 確認用ページ（GitHub Pages）を使えるようにする

1. **Settings → Pages** の「Build and deployment」の **Source** を **「GitHub Actions」** に変えます
2. **Settings → Environments** の **「github-pages」** を開き、「Deployment branches and tags」を **「No restriction」** に変えて保存します（なければ、一度下書きを保存すると作られます）

- 非公開（Private）のリポジトリでGitHub Pagesを使うには、GitHubの有料プランが必要です
- 確認用ページのURLは、知っていれば誰でも見られます（検索エンジンには載らない設定にしています）

### 1-4. 公開ボタンを「Squash and merge」だけにする

**Settings → General → Pull Requests** で、「Allow squash merging」だけにチェックを残し、その下の「Default commit message」を「Pull request title」にします。

### Claudeは何を読み込んで動くのか

| ファイル | 内容 |
| --- | --- |
| `CLAUDE.md` | 全体のルール（話し方、進め方、触ってよいファイル、守ること） |
| `.claude/skills/news/SKILL.md` | ニュースの作り方（記事ごとに必要な情報を洗い出す → 完成案 → 保存） |
| `.claude/skills/recruit/SKILL.md` | 採用情報（募集一覧、仕事、社員紹介、よくある質問、新しい職種）の変え方 |
| `.claude/skills/edit/SKILL.md` | 文章の修正、画像の差し替え、取り下げ、「確認中」の表示の消し方 |
| `.claude/skills/illustration/SKILL.md` | 写真がないときのイラストの描き方 |
| `.claude/skills/design/SKILL.md` | デザイン（色・文字・余白など）の変え方 |
| `.claude/skills/restore/SKILL.md` | 前の状態に戻すやり方 |

## 2. 使い方

### 依頼する

1. リポジトリの **「Issues」タブ → 「New issue」** を押します
2. タイトルに短い説明、本文に `@claude` とやりたいことを書いて「Create」を押します。写真は本文にドラッグ＆ドロップすれば添付できます
3. 1〜3分ほどで、Claudeがコメントで返事をします
4. 返事にはコメントで答えます。**コメントの先頭に `@claude` を付けてください**（付けないとClaudeは反応しません）

### 依頼の例

| やりたいこと | 書き方の例 |
| --- | --- |
| ニュースを出す | `@claude 2月の展示会の出展を告知したい`（案内状の画像を貼ってもよい） |
| 記事の相談をする | `@claude 何かニュースを出したいです。おすすめはありますか？` |
| 求人を増やす | `@claude グリーンプラの営業の募集を1件増やしたい`（求人票の画像を貼ってもよい） |
| 求人を直す | `@claude 倉吉工場の製造スタッフ（正社員）の給与を「月給22万円〜」に変えて` |
| 職種を増やす | `@claude 飲食の職種を増やしたい`（職種のページ・社員紹介・求人に要る情報を、AIがまとめて聞き返す。エントリーフォームの「ご希望の職種」の選択肢は、管理者が Xserver で足す） |
| 募集を締め切る | `@claude 倉吉工場の製造スタッフ（パート）の募集を締め切って` |
| 文章を直す | `@claude トップの「捨てるを、つくるに変える。」の下の紹介文を〇〇に変えて` |
| 写真を差し替える | `@claude アライアンスのページの新潟工場の写真をこれに変えて`（写真を貼る） |
| 「確認中」を消す | `@claude オープン採用の文面はこれで確定です。確認中の表示を消して` |
| 記事を取り下げる | `@claude 「2024NEW環境展」のニュースを消して` |
| 前の状態に戻す | `@claude 昨日公開したニュースを、公開前の状態に戻したい` |
| 消したものを戻す | `@claude 前に出していた倉吉工場のパートの募集をもう一度出したい` |

### 確認して公開する

1. Claudeが保存すると、1〜2分後にIssueに **「確認用ページを更新しました」** というコメントが届きます。今回変わったページのURLも並びます（上部に黄色い「確認用ページです」の帯が出ます）
2. 直したいところがあれば、同じIssueで `@claude ○○を直して` と頼みます
3. 問題がなければ、**Claudeの最新の返事** の下にある **「Create PR」** のリンクを押し、開いた画面で **「Create pull request」** を押します。これが公開申請です
4. 公開申請のページで **「Squash and merge」→「Confirm squash and merge」** を押します。2〜3分後に本番サイトに反映されます
5. 元のIssueが開いたままなら、「Close issue」で閉じます

### 注意

- **1つのIssueでは、1つの用件**を扱います。別の用件は新しいIssueで依頼してください
- 確認用ページでは、お問い合わせ・エントリーのフォームは表示されません（本番サイトだけで動きます）
- 新しいページの追加、メニューの変更、表示の仕方の変更は、Claudeは対応しません（管理者が行います）

### 困ったとき

| 困りごと | 対処 |
| --- | --- |
| Claudeが返事をしない | コメントに `@claude` が付いているか確認してください。Actionsタブで「Claude（Issueからの更新）」が失敗していないかも確認します |
| 確認用ページのURLが届かない | Actionsタブで「確認用ページを更新」の結果を確認します。失敗している場合は「1-3」の設定を見直してください |
| 確認用ページが変わらない | 反映まで1分ほどかかります。ページを再読み込みしてください |
| 急いで本番から消したい | 「Pull requests」タブの「Closed」から、その内容を公開したときの公開申請を開き、一番下の「Revert」→ 新しくできた公開申請で「Squash and merge」→「Confirm squash and merge」を押すと、2〜3分で元に戻ります |

## 3. 仕組みの詳細

### フォルダの構成

```
├── site/                  サイトの中身（サーバーの demo_wpt2 フォルダにそのまま置かれる）
│   ├── index.html など     各ページのHTML（data/ の JSON を読み込んで中身を表示する）
│   ├── data/               ニュース、採用情報、会社情報、製品の中身（JSON）
│   └── assets/             CSS、JavaScript、画像、PDF
├── tools/                 チェックと公開用のファイルづくり、画像の調整、画面の撮影
├── CLAUDE.md              Claudeへの作業ルール
├── .claude/skills/        Claudeの作業手順
└── .github/               自動処理の設定
```

### ワークフロー

| ファイル | 動くとき | すること |
| --- | --- | --- |
| `claude.yml` | Issueやコメントに `@claude` が書かれたとき | Issueの画像をダウンロードし、Claudeが返事・作業をする。下書きを保存したら確認用ページを作る |
| `preview.yml` | Claudeが下書きを保存したとき（`claude.yml` から呼び出される） | チェックして確認用のファイルをそろえ、GitHub Pages に公開し、URLをコメントで知らせる |
| `deploy.yml` | main に反映されたとき、毎朝6時ごろ | チェックして本番用のファイルをそろえ、Xserver の `/yamaguchi-index.com/public_html/demo_wpt2/` にアップロード、公開の記録（タグ）を残す |

### 公開用のファイルづくり（`tools/build.py`）

`site/` を `dist/` に写し、次のことを行います（担当者やClaudeが直すのは、これまでどおり `site/` の JSON と文章だけです）。

- JSON の書き方の誤り、記事のフォルダや画像の見落としをチェックする（誤りがあれば公開しない）
- ニュースの「下書き」「非公開」「日付が未来」の記事と、求人の「下書き」「非公開」を、本番用から外す
- 画像やCSSを差し替えたとき、ブラウザに古いものが残らないよう、`?v=` の番号を付け直す
- ページを一度ブラウザで開き、JSON から表示された中身を、そのまま HTML に書き込む（事前の書き込み）。JSON を読む表示処理はページから外す。検索エンジンやSNSでも中身が読めるようにするため。ニュース一覧の絞り込み・ページ送りは、JSON を読まない別の処理にしてあるので、そのまま動く
- すべてのページに書き込めたら、`data/` フォルダ（JSON）を外す。**本番・確認用のサーバーには JSON を置かない**。1ページでも書き込めなければエラーにして止める（本番は前の状態のまま）
- ページごとに、SNSで共有されたときのタイトル・説明・画像（OGP）を書き込む。本番のURLは `tools/build.py` の `SITE_URL`（変わったらここを直す）
- 確認用では、黄色い帯を出し、検索エンジンに載らないようにし、フォームを表示しない

### 手元で試す

```
pip install -r requirements.txt
python tools/build.py --check      # チェックだけ
python tools/build.py --preview    # 確認用を dist/ に作る
python tools/build.py              # 本番用を dist/ に作る
python tools/remove.py news 20251210        # 記事を消す（openings 番号 / jobs フォルダ名 / people 番号）
python tools/history.py list               # 前に消したものの一覧（show で中身、restore で戻す）
```

`dist/` のページは中身が書き込まれているので JSON は要りませんが、リンクや画像の場所を正しく見るため、`python -m http.server -d dist` などで小さなWebサーバーを立てて見てください。
`--no-prerender` を付けたときだけは書き込みをしないので、`data/` が残り、ページは JSON を読んで表示します（手元での確認用）。
