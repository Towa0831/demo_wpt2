# デザイン（CSS）の変更

見た目は `site/assets/style.css` の1つのファイルで決まっている。CLAUDE.md の「提案 → OK → 保存 の流れ」に沿って進める。

## 変えてよい範囲

- `site/assets/style.css`：色、文字、余白、配置、形、スマートフォン表示などを変えてよい
- HTML（`site/**/index.html`）は、これまでどおり **文言だけ**。タグ、`class`、`id`、`<script>` は変えない
- HTMLやページの仕組みを変えないとできない依頼（例:「メニューの並び順を変えたい」「新しい欄を足したい」「表示する項目を変えたい」）は、対応せず「管理者に相談してください」と伝える。CSSだけで実現できる場合（例: 横並びを縦並びにする）は対応してよい

## このサイトのCSSの作り

- ファイルの先頭の `:root` に、色・角の丸み・幅・書体がまとめてある

| 名前 | 今の値 | 使われているところ |
| --- | --- | --- |
| `--green` | `#3f9a4c` | メインの緑（英字の見出し、ボタン、リンク、アクセント） |
| `--green-d` | `#2f7f3b` | 濃い緑 |
| `--green-m`、`--green-l` | `#a4deab`、`#8fd29a` | 明るい緑（模様・飾り） |
| `--green-bg` | `#e3f1e5` | 薄い緑の背景 |
| `--ink`、`--body` | `#1f2321`、`#1a1d1b` | 見出しと本文の文字 |
| `--muted` | `#6b716e` | 補足の文字 |
| `--rule`、`--soft` | `#e2e6e4`、`#efefef` | 線、薄いグレーの背景 |
| `--radius` | `14px` | 角の丸み |
| `--font`、`--en` | Noto Sans JP、Inter | 日本語と英字の書体（Google Fonts） |

- ファイルは「基本 → ヘッダー → 共通の部品 → トップ → フッター → 下層の共通 → アライアンス → ニュース → 採用 → 表」の順に並んでいる。変えたい部品は、この区切りのコメント（`/* ---- ヘッダー */` など）から探す
- スマートフォン向けの指定は、それぞれの区切りの末尾の `@media (max-width: 960px)`（と `640px`）にある
- どの `class` がどこに使われているかは、そのページの `index.html` を開いて確かめる。JSON から表示される部分の `class` は、そのページの `<script>` の中に書かれている

## 1. 聞き取り

次のことが分からなければ質問する（一度に3つまで）。

- どこを変えたいか（サイト全体、ヘッダー、トップのメイン写真、ニュース一覧、採用のページ、スマートフォンでの表示など）
- どう変えたいか（色、大きさ、雰囲気など）。「もっと明るく」「やわらかく」のようなあいまいな希望は、具体案を2〜3案出して選んでもらう
- 参考にしたいサイトや画像があるか（あれば貼ってもらう）

## 2. 変える前の画面を撮る

```
python tools/screenshot.py before
```

`/tmp/issue-images/screens/` に、パソコン（`-pc`）とスマートフォン（`-sp`）の画面の画像が保存される。Read で開いて今の見た目を確かめる。特定のページを撮るときは、`python tools/screenshot.py before recruit/ news/` のように指定する。

## 3. 提案（ファイルはまだ変えない）

- 変える場所と内容を、見た目の言葉で箇条書きにする（例:「採用情報のボタン：緑の枠 → 緑の塗り」）
- 色は、色の名前とカラーコードを並べて書く（例: 少し濃い緑 `#2f8a3f`）
- 影響する範囲（「サイト全体のボタンが変わります」など）
- 大きな変更では、2〜3案に分けて選んでもらってもよい

## 4. 変える（OKが出てから）

- **色・角の丸み・書体は、まず `:root` の値を変える**。同じ色を各所に直接書かない。新しい色が必要なら `:root` に名前と説明のコメントを付けて足す
- HTML で使っている `class` 名を変えない・消さない
- **スマートフォン表示を必ず保つ**：`@media (max-width: …)` の部分を消さない。横にはみ出すような固定の幅を付けない
- **次の部分は消さない**：`.todo`（「確認中」の印。制作中の確認に必要）、`.nav-toggle` と `.nav-open`（スマートフォンのメニュー）、`.slides` と `.is-on`（トップの写真の切り替え）
- **読みやすさ**：文字と背景の色の差を十分にとる。本文の文字を今より小さくしない
- **書体**：Google Fonts 以外の外部ファイルは読み込まない。書体を変えるときは、全ページの `<head>` の Google Fonts の指定も変える必要があるので、管理者に相談するよう伝える
- コメント（`/* 〜 */`）は日本語で、何のための設定かが分かるように書く
- CSSを変えると、公開のときに読み込みの番号（`?v=`）が自動で付け直されるので、HTMLの番号は書き換えなくてよい

## 5. 変えた後の画面を確かめる（必ず行う）

```
python tools/build.py --check
python tools/screenshot.py after
```

- `after-` で始まる画像を Read で開き、`before-` の画像と見比べる
- 確かめること: 頼まれたとおりに変わっているか／文字が読みにくくなっていないか／要素が重なったり、はみ出したりしていないか／スマートフォン（`-sp`）で崩れていないか
- 「横にはみ出しています」と表示されたら、`before` でも出ていたかを見る。`after` だけで出ていたら、今回の変更が原因なので直す
- おかしなところがあれば直して、もう一度撮る（2回まで。それでも難しければ、変更を小さくする）

## 6. 保存と返事

CLAUDE.md の「保存のしかた」に従う。返事には次のことも書く。

- 変えた内容を見た目の言葉で箇条書き（変更前 → 変更後）
- 「確認用ページは、パソコンとスマートフォンの両方で見てください」
- 元に戻したいときは `@claude デザインを変更前に戻して` と頼めば戻せること

## 戻すとき

デザインを元に戻す依頼は、restore の手順書に従う。`site/assets/style.css` の履歴を調べて戻す（`git log -- site/assets/style.css`、`git restore --source=<戻す先> -- site/assets/style.css`）。
