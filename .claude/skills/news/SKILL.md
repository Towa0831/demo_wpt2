# ニュースの記事をつくる

担当者がやるのは **「何を出すか決めること」** と **「公開してよいと判断すること」** だけ。
文章・画像・見せ方は、あなたが考えて提案する。担当者に書き方を考えさせない。

**記事の決まった形（型）や、決まった項目の一覧はない。** 記事ごとに、「誰が読むか」「読んだ人に何をしてほしいか」から、必要な情報と組み立てをその都度考える。ほかの記事の組み立てをまねしない。

1回の返事で1つの段階だけ進める。

| 段階 | あなたがすること | ファイル |
| --- | --- | --- |
| ① 洗い出し | この記事に必要な情報を洗い出し、担当者にしか分からないことだけを聞く | 変えない |
| ② 完成案 | 記事の完成案（タイトル案・本文・画像の案・日付）を全文で見せる | 変えない |
| ③ 修正 | 意見を反映した完成案を見せ直す（OKが出るまで） | 変えない |
| ④ 保存 | 記事と画像を作り、チェックして下書きとして保存する | 作る |

最初の依頼に、記事に必要な情報がすべて書かれていたら、① で何も聞かずに ② から始めてよい。

## ① 洗い出し

### 1. 調べる

- `python tools/build.py --check` で今日の日付を確かめる
- `site/data/news.json` の `items`（記事）を見る。同じ話題の記事がすでにあれば、新しく作るか、その記事を直すかを確認する
- `site/data/news.json` の `companies`（会社）と `categories`（カテゴリ）の一覧を見る
- `site/data/site.json` の各社の情報（`companies`）を見る
- チラシや案内状などの画像が貼られていれば、内容を読み取る（読み取れない部分は推測しない）

### 2. 考える（返事には書かなくてよい）

- **読むのは誰か**：取引先、地域の方、これから応募する人、アライアンス各社の社員 など
- **読んだ人に何をしてほしいか**：来てほしい、協力してほしい、問い合わせてほしい、知っておいてほしい など
- **そのために読む人が知りたいこと**：その人の立場で、読んだあとに迷うこと・困ることを考える（いつ、どこ、誰が対象か、費用、申し込み方法、問い合わせ先 など。必要なものだけ）
- **この記事ならではの話題**：今回が初めてのこと、具体的な数字、関わった人の声、始めた理由や背景、写真になる場面
- **間違えると困る事実**：日付、時間、金額、場所、URL、会社名

### 3. 返事を書く

**返事の形や言い回しは決まっていない。** この記事に合わせて、自然な文章で書く。ほかの記事のときの返事をまねしない。

- **聞くのは、この記事について担当者にしか分からないことだけ**
  - 「2. 考える」で出てきたことのうち、Issue・資料・JSON から分からないものを聞く
  - 必ず必要なことと、あると記事がよくなること（話題、人の声など）の区別が分かるように書く
  - なぜ必要かを短く添える（例:「ブース番号（会場で探してもらうため）」）
  - 項目の数は記事に合わせる。すでに分かっていて聞くことがなければ、何も聞かずに ② の完成案に進んでよい
- **毎回同じことを聞かない**
  - 日付・画像・会社・カテゴリなどを、決まりごととして毎回聞かない
  - 聞かなくても決められることは、聞かずに ② の完成案の中で「こうします」と示す（例: 日付は今日、会社は依頼した人の会社）。変えたいときは担当者が言えばよい
  - 写真については、この記事に使えそうな写真が担当者の手元にありそうなときだけ、具体的に頼む（例:「授賞式の写真があれば貼ってください」）
- **聞くことは、まとめてコピーできる形にする**：担当者がコピーして埋め、そのまま返事にできるよう、コードブロック（` ``` `）で囲み、1行目を `@claude` にする
- **記事の方向性**：何を中心に伝えるかで記事が大きく変わるときだけ、案を短く示して選んでもらう
- 見た目や書き方（表にするか、見出しをどうするか）は聞かない。あなたが決める
- 最後に「次にやること」を書く

聞くことが多くても、質問は1回の返事にまとめる（CLAUDE.md の「質問は3つまで」の例外）。

### 漠然とした依頼のとき

「何か記事を出したい」「おすすめは？」「しばらく更新していない」のような依頼には、記事のネタを3〜5個、番号付きで提案する。

- 今日の日付から、これからの時期の行事・展示会・季節・営業に関わること
- 今ある記事の続き（出展した展示会の報告、始めた取り組みのその後 など）や、しばらく出ていない話題・会社
- `site.json` の会社情報や `products.json` の製品から考えられること
- すでに同じ内容の記事があるものは出さない
- 各案に、どんな記事になるかと、用意してほしい情報を1行ずつ添える
- 「番号で選んでください（例: `@claude 2番で`）」と案内する。選ばれたら、その記事について ① の 2 から進める

## ② 完成案

記事に必要なことがそろったら、次のことをコメントに見やすく書く。**ファイルはまだ作らない。**
① で聞かずに決めたことは、ここで「こうします」と示す。

- **タイトル案**：「案1」〜「案3」。それぞれ切り口を変える（内容がひと目で分かるもの）
- **会社とカテゴリ**：`news.json` の `companies`・`categories` にある名前から選ぶ（例: ウッドプラスチックテクノロジー／展示会・イベント）
- **日付**：すぐ公開なら今日。未来の日付にすると「〇月〇日の朝6時ごろに自動で公開されます」と書く
- **最初の段落**：一覧やページの説明にも使われる、記事の要点（1〜3文）
- **本文**：完成形を全文で（下の「本文の組み立て方」）
- **画像**：何をどこに載せるか。写真が貼られていればその写真を使う。写真がなければ、記事に合うイラストの案（描く内容を言葉で書き「写真ではなくイラストです」と明記する。`.claude/skills/illustration/SKILL.md` の「1. 提案」）か、画像なしのどちらかを、記事に合わせて選んで示す
- **入れなかった情報**：担当者からもらった情報や指示のうち、記事に入れなかったものがあれば、その理由（なければ書かない）
- **確認してほしい点**：日付・URLなど、間違えると困る部分を1〜3個

必要なことに「未定」があるときは、その部分を「決まり次第、お知らせします」とした案にする。確定したら `@claude ブース番号は〇〇に決まりました` のように頼めば追記できることを添える。

最後に「次にやること」として、「この内容でよければ `@claude 案1でOK` のようにコメントしてください。直したいところは `@claude 本文の〇〇を△△に` のように書いてください」と書く。

### 本文の組み立て方

**決まった並び順はない。** 読む人と伝えたいことから、毎回組み立てを考える。

- 最初の段落で、何についての記事か分かるようにする
- 読む人がいちばん知りたいことは、探さなくても見つかる位置に置く
- 書き方は、内容の形に合わせて選ぶ。項目と内容の組がいくつもあるなら表、並べるものは「・」で始まる行にする。背景や思い、当日の様子は文章で書く。何でも表にしない
- 長い記事は小見出しで区切る。短い記事は小見出しなしでよい
- 言葉づかいは読む人に合わせる。1文を短く。「〜させていただきます」の連続は避ける
- 日付は「2026年12月9日（水）」のように曜日を付ける。曜日は必ず `python tools/build.py --weekday 日付` で確かめる
- 事実（日付、時間、金額、場所、人数、URL など）は、担当者からもらったものだけを書く

このサイトの記事で使える書き方は、次の6つだけ（太字や文字の色、HTMLのタグは使えない）。

| 書き方 | 使いどころ |
| --- | --- |
| 段落 | ふつうの文章。行を変えたいところで改行できる |
| 小見出し | 長い記事の区切り |
| 表 | 「会場」「日程」「入場料」のような、項目と内容の組（2列）。スマートフォンでは内容の列が狭いので、会場名と小間番号、日付と時間などは改行で分ける |
| 画像 | 写真やイラスト。説明（alt）を必ず付ける |
| リンク | ほかのページや外部のサイトへ。表示する文字を付ける |
| PDF | チラシや資料のPDFへのリンク。表示する文字を付ける |

## ③ 修正

意見を反映した完成案を、もう一度全文で見せる。どこを変えたかを冒頭に1〜2行で書く。

## ④ 保存（OKが出てから）

1. 記事のフォルダ名（slug）を決める：日付の数字8けた（例: `20261105`）。同じ日付の記事がすでにあれば `20261105-2` のように番号を付ける
2. `site/data/news.json` の `items` のいちばん上に、記事を1件足す（下の「データの形式」）
3. 記事のページを作る：ほかの記事のフォルダの `index.html` をそのままコピーする（中身は書き換えない）
   ```
   mkdir -p site/news/20261105
   cp site/news/20251210/index.html site/news/20261105/index.html
   ```
4. 画像や資料を用意する
   - 写真：`python tools/prepare_image.py /tmp/issue-images/image-1.jpg site/assets/img/news/news_20261105_booth.jpg`
   - イラスト：`.claude/skills/illustration/SKILL.md` の「2. 描く」「3. 見た目を確かめる」
   - PDF：`site/assets/doc/` に置く（`cp` でコピー。ファイル名は半角英数字）
5. **もらった情報との照らし合わせ**：担当者からもらった情報と、コメントの指示（「最後に〇〇と入れて」など）を1つずつ見て、記事に入っているかを確かめる。抜けていれば足す
6. `python tools/build.py --check` でエラーがないことを確かめる。エラーがあれば直す
7. `python tools/screenshot.py after news/20261105/ news/` で記事のページと一覧を撮り、パソコン（`-pc`）とスマートフォン（`-sp`）の画像を Read で開いて、読みやすいか、表や画像が正しく出ているかを確かめる
8. CLAUDE.md の「保存のしかた」に従って保存し、返事をする。返事には次のことも書く
   - 追加した記事のタイトルと日付
   - 確認用ページで特に見てほしいところ（日付、リンク先など）
   - 間違いに気づいたら `@claude 日程を〇〇に直して` のように頼めば直せること

## データの形式（`site/data/news.json` の `items` の1件）

```
{
  "d": "2026.11.05",
  "slug": "20261105",
  "t": "記事のタイトル",
  "co": ["wpt"],
  "ca": ["event"],
  "lead": "最初の段落。一覧やページの説明にも使われる。",
  "blocks": [
    { "t": "h", "v": "小見出し" },
    { "t": "p", "v": "段落の文章。\n改行したいところは \\n と書く。" },
    { "t": "table", "v": [["会場", "東京ビッグサイト\nブース番号 046"], ["日程", "2026年2月12日(木)～2月13日(金)"]] },
    { "t": "image", "v": "/assets/img/news/news_20261105_booth.jpg", "alt": "ブースの様子" },
    { "t": "link", "v": "/news/20251210/", "label": "関連記事：クリアホルダー回収プロジェクト" },
    { "t": "pdf", "v": "/assets/doc/20261105_flyer.pdf", "label": "チラシ（PDF）" }
  ]
}
```

- `d`：日付（`2026.11.05` の形）。未来の日付にすると、その日の朝6時ごろに自動で公開される（予約公開）。確認用ページでは「公開予定」と付けて表示される
- `slug`：記事のフォルダ名と同じにする
- `t`：タイトル
- `co`：会社のコード（`news.json` の `companies` のどれか。複数可）
- `ca`：カテゴリのコード（`news.json` の `categories` のどれか。複数可）。新しいカテゴリが必要そうなときは、作る前に担当者に確認する
- `lead`：最初の段落
- `blocks`：本文。上から順に表示される（上の表の6つの書き方）
- `status`：（任意）書かなければ公開。担当者が「まだ公開しない」と言ったときは `"status": "下書き"`（確認用ページにだけ出る）。取り下げは `"status": "非公開"`
- `src`：（任意）同じ記事が各社のサイトにもあるときの、元の記事のURL。ページには表示されない
- 画像・資料・サイト内のページは `/assets/…`、`/news/…` のように `/` から始めて書く。外部のサイトは `https://…` で書く
- JSON の文字の中で `"` を使うときは `\"` と書く（「」を使えば気にしなくてよい）
