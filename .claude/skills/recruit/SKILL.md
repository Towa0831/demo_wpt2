# 採用情報を変える

採用情報の中身は、すべて `site/data/recruit.json` にある（各社の名前は `site/data/site.json` の `companies`）。
CLAUDE.md の「提案 → OK → 保存 の流れ」に沿って進める。小さな修正（「給与を〇〇に」など）は、すぐ保存してよい。

## recruit.json の中身と、表示されるページ

| 項目 | 中身 | 表示されるページ |
| --- | --- | --- |
| `openings` | 募集一覧の求人（1件ずつ） | 募集一覧（`recruit/career/`） |
| `jobs` | 職種（1件が1つの職種）。仕事の紹介、1日の流れ（`day`）、キャリア（`career`） | 仕事を知る（`recruit/jobs/` と `recruit/jobs/フォルダ名/`）、採用トップ、サイトのトップ |
| `people` | 社員紹介。質問と答え（`qa`） | 人を知る（`recruit/people/` と `recruit/people/フォルダ名/`）、採用トップ |
| `faq` | よくある質問（分類ごとに、[質問, 答え] の組） | よくある質問（`recruit/faq/`） |
| `open` | 新卒・オープン採用の説明 | オープン採用（`recruit/open/`） |
| `message`、`lead`、`policy`、`conditionsNote`、`factory` | 採用メッセージ、採用全体の説明、工場の紹介 | 採用トップ（`recruit/`） |

`todo` や `〇〇Todo` は、ページに「確認中」と表示されるメモ。担当者が確定したと言ったときだけ消す（edit の手順書の「確認中の表示を消す」）。

## 1. 募集一覧の求人（openings）

### 1件の形

```
{
  "co": "wpt",
  "job": "manufacturing",
  "title": "製造スタッフ（正社員）",
  "site": "倉吉工場",
  "pref": "鳥取",
  "emp": "正社員",
  "todo": false,
  "area": "鳥取県倉吉市",
  "hours": "8:30〜17:30（休憩あり）",
  "holiday": "会社カレンダーによる",
  "desc": "仕事の内容",
  "req": "応募の条件",
  "pay": "給与",
  "benefits": "待遇・福利厚生"
}
```

- `co`：募集する会社（`site.json` の `companies` の `id`。採用をしている会社は `recruit` が true のもの）
- `job`：職種（`jobs` にある `slug` のどれか。今ない職種の求人なら、先に「3. 新しい職種を増やす」）
- `emp`：雇用形態（正社員、パートなど）
- `todo`：内容が仮のときは `true`（「確認中」と表示）、確定したら `false`
- `status`：（任意）書かなければ公開。まだ出さないときは `"status": "下書き"`（確認用ページにだけ出る）、締め切ったら `"status": "非公開"`

### 求人を増やす

1. 担当者から、上の項目にあたる情報をもらう。足りないものは、コピーして埋められる形でまとめて聞く
   - 求人票（ハローワークの求人票など）の画像やPDFの画像が貼られたら、読み取って埋める。読み取れない部分は推測しない
   - 給与・勤務時間・休日・勤務地は、必ず担当者からもらったものを書く
2. 求人の案を見せて、OKをもらう
3. `openings` に1件足す（同じ会社・職種の求人の近くに入れる）

### 求人を直す・締め切る

- 「〇〇を△△に」のように具体的なら、すぐ保存してよい（変更前 → 変更後を返事に書く）
- 締め切るときは、項目を消さずに `"status": "非公開"` を付ける（`todo` の後ろなど、どこに書いてもよい）。返事の最後に「また募集するときは `@claude 〇〇の募集を再開して` と頼めば戻せます」と添える。再開するときは `status` を消す
- 対象がはっきりしないときは、`openings` の一覧（会社・タイトル・勤務地）を番号付きの表で見せて選んでもらう
- 求人を増やしたり締め切ったりしたら、採用ページの説明文（`policy`、`lead`、`conditionsNote` など）に、食い違う文がないかを確かめる（例: パートの募集がなくなったのに「パートの募集も掲載しています」と書いてある）。あれば直さずに、直すかどうかを担当者に聞く

### 表現のチェック

求人の文章を作る・直すときは、次のことを確かめる。当てはまるときは、言い換えを提案する。

- 性別を限る言葉を使わない（「営業マン」→「営業スタッフ」、「女性歓迎」は書かない）
- 年齢を限る言葉を使わない（「若手」「〇歳まで」は、例外にあたるかを担当者に確認する）
- 「誰でもすぐ稼げる」のような、実際と違う印象を与える書き方をしない
- 給与は、固定残業代や手当が含まれるかを分かるように書く

## 2. 仕事の紹介（jobs）・社員紹介（people）

- 文章や1日の流れ、質問と答えを直すのは、edit の手順書と同じやり方でよい
- 社員紹介の本文はご本人の言葉なので、言い回しを変えるときは必ず提案してOKをもらう
- 社員紹介を1人増やすとき
  1. 名前（表示する呼び方）、職種、勤務地、写真、質問と答えをもらう
  2. `people` に1件足す。`slug` は2けたの番号（`04` など）で、ほかと重ならないもの。形は今ある1件と同じ

     ```
     {
       "slug": "04",
       "name": "〇〇さん",
       "jobSlug": "food",
       "where": "東京・本社",
       "title": "見出し（ご本人の言葉から一文）",
       "lead": "ひとこと",
       "role": "所属・役職",
       "joined": "2020年4月入社",
       "prev": "前職：〇〇",
       "img": "/assets/img/photo/person-名前.jpg",
       "todo": "原稿がご本人の確認前のときなどに書く",
       "qa": [
         { "q": "質問", "a": ["答えの段落", "次の段落"] },
         { "img": "/assets/img/photo/写真.jpg", "cap": "途中に入れる写真の説明" }
       ]
     }
     ```

     写真がまだないときは `img` を書かない（「撮影予定」の枠が出る）
  3. ページを作る：ほかの社員紹介のフォルダの `index.html` をそのままコピーする
     ```
     mkdir -p site/recruit/people/04
     cp site/recruit/people/01/index.html site/recruit/people/04/index.html
     ```
  4. 写真は `python tools/prepare_image.py 元の画像 site/assets/img/photo/person-名前.jpg` で保存し、`img` に `/assets/img/photo/person-名前.jpg` と書く
- 新しい職種を増やすときは、下の「3. 新しい職種を増やす」

## 3. 新しい職種を増やす

「飲食の職種を増やしたい」「品質管理の募集を始めたい」のように、`jobs` にない職種の依頼。今ある職種と同じように、次のものがそろうようにする。

| 出るところ | 中身 | 作り方 |
| --- | --- | --- |
| 職種のページ（`recruit/jobs/フォルダ名/`） | 職種名、ひとこと、仕事内容、勤務地、写真、1日の流れ、キャリアの道筋、この職種の人、募集中の求人 | `jobs` に1件足し、フォルダをコピーする |
| 仕事を知る・採用トップ・サイトのトップ | 職種のカード | `jobs` に足せば自動で出る（並びは `jobs` の順） |
| 人を知る | この職種の社員紹介 | `people` に足す（上の 2.） |
| 募集一覧 | この職種の求人 | `openings` に足す（上の 1.） |
| 職種の数を書いた文 | 「4つの職種」など | 文言を直す（下の ③ の 5） |
| エントリーフォームの「ご希望の職種」 | 選択肢 | ホームページとは別の設定（Xserver）なので直せない。管理者に頼むよう担当者に伝える |

### ① 聞く（最初の返事）

今ある職種（`jobs` の1件と、その職種の `people`・`openings`）を読み、同じくらいの中身で作るために要る情報を、まとめて聞く。コピーして埋められる形にし、1行目を `@claude` にする。

- 分からないところは「未定」と書いてもらえばよいと添える（「確認中」と表示して、あとで直せる）
- 社員紹介と求人は、あとからでもよいと添える（求人がない間は、職種のページに「いま、この職種の募集はありません」と出る）
- 職種名は、エントリーフォームの選択肢と同じ文字にする必要があるので、正式な名前を書いてもらう

聞く内容の例（職種に合わせて言葉を変えてよい。今の職種のページにない項目は足さない）:

```
@claude
【職種】
・職種名：
・主な勤務地：
・どんな仕事か（箇条書きのメモでかまいません）：
・1日の流れ（時刻と、すること）：
・入社してからのキャリア（入社〜1年、2〜3年、その先 など）：
・仕事の様子の写真（このコメントに貼ってください。なければ「なし」）：

【社員紹介】（載せる場合。あとからでも大丈夫です）
・お名前（「〇〇さん」の形で載せます）、所属・役職、入社した年、前職：
・写真（なければ「なし」）：
・インタビュー（質問と答え。メモでかまいません）：
・ご本人の掲載の了承：済み／まだ

【求人】（すぐ募集する場合。ハローワークの求人票の画像でも大丈夫です）
・会社、勤務地、雇用形態、勤務時間、休日、給与、仕事内容、応募の条件、待遇
```

### ② 提案（もらった情報で、全文を見せる）

- **職種のページ**：職種名、ひとこと（`lead`。今の職種のような短い一文）、仕事内容（`desc`）、勤務地（`where`）、1日の流れ（表）、キャリアの道筋（表）、写真（あり／撮影予定）
- **社員紹介**：見出し（`title`。ご本人の言葉から一文）、ひとこと（`lead`）、質問と答え。ご本人の言葉なので、メモを質問と答えの形に整えるだけにし、言っていないことは足さない
- **求人**：「1. 募集一覧の求人」の形で
- **職種の数を書いた文**：変更前 → 変更後（③ の 5 の場所すべて）。「製造の現場から、営業、事務まで。」のように職種を並べた文に新しい職種が合わないときは、言い回しの案も出す
- **並び順**：カードのどこに入れるか。希望がなければ最後
- 勤務地・時刻・給与などの事実は、担当者からもらったものだけを書く。「未定」のところは「確認中」のメモ（`dayTodo`、`careerTodo`、`todo`）を付ける

### ③ 保存（OKが出てから）

1. `jobs` に1件足す（並び順の位置に）

   ```
   {
     "slug": "food",
     "code": "05",
     "name": "飲食",
     "where": "東京／大阪",
     "lead": "ひとこと",
     "desc": "仕事内容。段落を分けるときは \n",
     "img": "/assets/img/photo/job-food.jpg",
     "day": [["9:00", "開店準備"], ["11:00", "ランチの営業"]],
     "career": [["入社〜1年", "できるようになること"], ["2〜3年", "…"]],
     "dayTodo": "仮の時刻があるときだけ書く",
     "careerTodo": "仮の内容があるときだけ書く"
   }
   ```

   - `slug`：ページの場所（URL）になる。職種を表す短い英語で、半角の英小文字・数字・ハイフン（`food`、`quality`、`driver` など）。あとから変えない
   - `code`：今ある職種の続きの2けたの番号
   - 写真がないときは `"img": ""` にして、`"imgPlan": "どんな写真を撮る予定か"` を書く（「撮影予定」の枠が出る）。撮る時期が分かっていれば `"imgNote": "〇月の撮影時に撮る"` も書く
2. ページを作る（ほかの職種のフォルダの `index.html` をそのままコピーする。中は書き換えない）

   ```
   mkdir -p site/recruit/jobs/food
   cp site/recruit/jobs/manufacturing/index.html site/recruit/jobs/food/index.html
   ```

3. 写真があれば `python tools/prepare_image.py 元の画像 site/assets/img/photo/job-food.jpg`
4. 社員紹介・求人があれば、上の 2.・1. の手順で足す（`people` の `jobSlug`、`openings` の `job` に新しい `slug` を書く）
   - ご本人の掲載の了承が「まだ」のときは、社員紹介は足さない（社員紹介には下書きの仕組みがないため）。了承が取れたら、あらためて頼んでもらう
5. 職種の数を書いた文を直す（文言の修正なので、HTMLを直してよい）。今あるのは次の場所
   - サイトのトップ（`site/index.html`）：「4つの職種で人を募集しています」とその前の一文
   - 採用トップ（`site/recruit/index.html`）：「資源循環を支える、4つの職種があります」と、ページの説明（`<meta name="description">` の `content`）の「4職種」
   - 仕事を知る（`site/recruit/jobs/index.html`）：ページの説明「製造、設備保全・生産技術、営業、事務・企画管理の4職種。」（職種名も並んでいる）
   - `recruit.json` の `lead`：「職種は4つに分かれています」

   `python tools/build.py --check` は、職種の数と合わない文をエラーで教えてくれる。全部直すまで保存しない
6. `python tools/build.py --check` でエラーがないことを確かめ、`python tools/screenshot.py after / recruit/ recruit/jobs/ recruit/jobs/food/` で撮って、Read で開いて確かめる（社員紹介を足したら `recruit/people/` も）
7. CLAUDE.md の「保存のしかた」に従って保存する。返事には、確認用ページの職種のページのURLと、次の一文を必ず入れる

   > エントリーフォームの「ご希望の職種」に「（職種名）」を足す作業は、ホームページとは別の設定なので、管理者に頼んでください。足すまでは、フォームの選択肢にこの職種がありません。

### 職種の名前を変える・職種をなくす

- 名前を変える：`jobs` の `name` を直し、③ の 5 の文に職種名が並んでいれば直す。`slug`（ページの場所）は変えない。エントリーフォームの選択肢も合わせる必要があるので、③ の 7 と同じく管理者に頼むよう伝える
- 職種をなくす（ページを取り下げる）依頼は、管理者に相談するよう伝える

## 4. よくある質問（faq）

- `faq` は分類（`cat`）ごとに、`items` に `["質問", "答え"]` の組が並んでいる
- 質問を足すときは、合う分類の `items` に足す。合う分類がなければ、新しい分類を作る前に担当者に確認する
- 答えの頭の「【仮】」は、担当者が確定したと言ったら消す

## 5. 確かめて保存する

1. `python tools/build.py --check` でエラーがないことを確かめる
2. 変えたページを `python tools/screenshot.py after recruit/career/` のように撮り、Read で開いて表示を確かめる
3. CLAUDE.md の「保存のしかた」に従って保存する
