# 文章の修正・画像の差し替え・取り下げ

CLAUDE.md の「依頼の種類と進め方」に沿って進める。

## 1. 直す場所を探す

担当者は、ページの見た目やURLで場所を伝えてくる。文章は **JSON（`site/data/`）と HTML（`site/**/index.html`）の両方** にあるので、次の順で探す。

1. 担当者が書いた文言（直したい元の文章）で検索する
   - Grep で `site/data/` と `site/` の `*.html` を検索する（例:「捨てるを」「倉吉工場」を探す）
   - 文章の途中に改行や `<br>` が入っていることがあるので、見つからなければ短い言葉で探し直す
2. URLやページ名で伝えられたら、下の表で探す場所を絞る

| ページ | 文章のありか |
| --- | --- |
| トップ（`site/index.html`） | 大きな見出し、紹介文、各欄の見出しは HTML。数字・循環・代表メッセージ・参画企業は `site.json`、ニュース欄は `news.json`、採用欄は `recruit.json` |
| アライアンス（`site/alliance/`） | 各社・拠点・数字・沿革・物語などは `site.json`、製品は `products.json`、ページの見出しは HTML |
| ニュース（`site/news/`） | 記事はすべて `news.json`。一覧ページの説明文は `site/news/index.html` |
| 採用情報（`site/recruit/` の各ページ） | `recruit.json`（各社の名前は `site.json`）。中身の変更は recruit の手順書に従う |
| お問い合わせ・エントリー | 各ページの `index.html`。フォームそのものは別の仕組みなので、ここでは直せない（管理者に相談） |
| ヘッダー・フッター | すべてのページの `index.html` に同じものが書かれている |

- 見つからない、または **同じ文言が複数の場所にある** ときは、場所の候補を見せて、どれを直すか（全部か）を確認する
- ヘッダーやフッターのように全ページ共通の部分は、すべてのページを同じように直す（1ページだけ直すと、ページによって表示が違ってしまう）
- 依頼が「新しいページを作りたい」「メニューを変えたい」「表示の仕方を変えたい」などのときは、対応せず管理者に相談するよう伝える（ニュースの記事は news、職種・社員紹介を増やすのは recruit の手順書で対応する）

## 2. 文章を直す

- 直し方が具体的（「〇〇を△△に」）なら、すぐ保存してよい。返事に **変更前 → 変更後** を書く
- 「もっと分かりやすく」「やわらかく」など、言い回しを考える必要があるときは、修正案を示してOKをもらってから保存する
- 日付に曜日を書くときは `python tools/build.py --weekday 日付` で確かめる

### JSON を直すときの決まり

- 直すのは `"…"` の中の文字だけ。項目の名前、`[ ]` `{ }` の形、`,` の位置は変えない
- 文字の中で改行するところは `\n` と書く。`"` を使うときは `\"` と書く
- 直したら必ず `python tools/build.py --check` を実行する（書き方の誤りがあると、そのページが表示されなくなるため）

### HTML を直すときの決まり

- タグの間の文字だけを直す。タグ、`class`、`id`、`<script>` の中身は変えない
- `<br>` や `<span class="…">` などで文章が分かれているときは、その分け方を保ったまま直す

## 3. 画像を追加・差し替える

1. `/tmp/issue-images/list.txt` で、使う画像を確認する。画像が複数あり、どれを使うかはっきりしないときは確認する
2. どこに使うかがはっきりしないときは、候補を示して確認する
3. 画像を整えて保存する。差し替えのときも、**元の画像は上書きせず、新しい名前で保存する**（古い画像は履歴として残し、ブラウザに古い画像が残る問題も防ぐ）
   ```
   python tools/prepare_image.py /tmp/issue-images/image-1.jpg site/assets/img/photo/exterior-2026.jpg
   ```
4. 画像を指定している場所を、新しいファイル名に書き換える
   - JSON の中：`"/assets/img/photo/exterior-2026.jpg"` のように `/assets/` から書く
   - HTML の中：`src="../assets/img/photo/exterior.jpg?v=…"` のように、そのページからの場所で書かれている。ファイル名の部分だけを書き換え、`?v=…` はそのまま残す（公開のときに自動で付け直される）
   - 古いファイル名がほかで使われていないか、Grep で確認する
5. 画像の説明（`alt`、JSON では `alt` や `img` の近くの説明の項目）は、画像の内容が分かる短い文にする
6. 返事には、どこの画像をどう変えたかと、整えた結果（サイズなど）を書く

イラストを新しく描く・描き直すときは、`.claude/skills/illustration/SKILL.md` に従う。

## 4. ニュースを取り下げる（削除）

- ファイルやフォルダは削除しない。`news.json` のその記事に `"status": "非公開"` を付ける
  - 担当者が「削除して」「完全に消して」と書いていても同じ。返事で「あとで元に戻せるよう、データは残したまま非公開にしました。ホームページからは見えなくなります」と伝える
- 対象の記事がはっきりしているとき（タイトルが1つに決まるとき）は、確認を待たずに非公開にして保存してよい。返事に **どの記事を非公開にしたか**（タイトルと日付）を書く
- 非公開にすると、確認用ページでも一覧と記事のページから消える。公開ボタンを押すと、本番でも消える（記事のURLを開くと「見つかりません」になる）
- 返事の最後に「元に戻したいときは `@claude 〇〇の記事を元に戻して` と頼めば、公開の状態に戻せます」と添える
- 戻すときは `"status": "非公開"` を消す
- 対象がはっきりしないときは、記事の一覧（タイトル・日付）を番号付きの表で見せて選んでもらう
- 募集一覧の求人を締め切るときは、recruit の手順書に従う

## 5. 「確認中」の表示を消す

ページの「確認中」の印は、制作中の確認メモ。担当者が「この内容で確定した」と言ったときだけ消す。

- JSON の `todo`（や `〇〇Todo`）の項目：中身を空にする（`"todo": ""`）。`true` になっているものは `false` にする。項目そのものは消さない
- 文章の頭の「【仮】」：その文章が確定したら「【仮】」を消す
- HTML の `<p class="todo">…</p>`：その `<p>` を丸ごと消してよい（このときだけ、タグを消してよい）
- どの「確認中」を消すのかがはっきりしないときは、ページにある「確認中」の一覧を見せて確認する

## 6. 保存

CLAUDE.md の「保存のしかた」に従う。
